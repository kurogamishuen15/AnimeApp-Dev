# Auditoría focalizada — error al cambiar de servidor — 2026-11-12

## Resultado

Se corrigió una causa reproducible del mensaje `Playback command failed.` en
una selección de audio que sobrevivía al cambio de medio. El menú retenía una
pista nativa de la fuente anterior; al seleccionar después de un cambio, la UI
leía la generación vigente y enviaba el ID viejo al coordinator/adaptador. La
prueba de widget reprodujo el mensaje exacto antes de la corrección.

El cambio de contexto de medios ahora invalida de forma síncrona las opciones
de audio abiertas al solicitar `open`, un cambio de fuente o Stop, antes de que
la operación correspondiente empiece en la cola FIFO. El item del menú guarda
ID nativo, generación activa y revisión de contexto. La UI descarta la
selección obsoleta sin emitir un comando al motor ni mostrar un fallo de
reproducción por una acción que ya dejó de ser válida.

La ruta nativa normal de Morevna A↔B, la conservación de posición alrededor de
00:40, el cambio desde pausa, Play/Pause, seek relativo y rollback de HTTP 503
pasaron con libmpv. No se pudo interactuar con la ventana Fedora en este corte;
por tanto, el clic manual que originó el reporte no fue repetido visualmente.
La causa reproducida es concreta y compatible con ese síntoma, pero la falta de
un registro de interacción de la captura del propietario impide atribuirle con
certeza exclusiva aquella selección física. La fase queda **PENDIENTE**, sin
cierre documental.

## Hallazgos

### F27-SW-01 — P2, corregido: una pista de menú antigua se enviaba al medio nuevo

- Archivos: `app/lib/app/player/audio_track_selector.dart`,
  `app/lib/app/player/spike_player_page.dart`.
- Evidencia: la regresión de widget abría el menú de audio para source A,
  actualizaba el medio a B y seleccionaba la opción todavía visible de A. Antes
  del cambio, el callback emparejaba el ID nativo antiguo con la generación
  actual; el fake del adaptador rechazó el ID y la página mostró exactamente
  `Playback command failed.`.
- Causa demostrada en ese recorrido: la identidad nativa del track y la
  generación usada por el callback se obtenían en momentos distintos.
- Corrección: cada valor del `PopupMenuButton` conserva `(id,
  sourceGeneration, mediaContextRevision)`. El callback comprueba el contexto
  antes de pedir selección al coordinator. Los IDs no se reutilizan entre
  medios.
- Prueba: `stale audio menu cannot send an old native track after source
  change`; pasa y comprueba que la opción antigua no llega al engine y no deja
  el mensaje genérico.
- Estado: corregido para la causa reproducida.

### F27-SW-02 — P2, corregido: petición nueva aún encolada no invalidaba menú

- Encontrado en primera pasada independiente `auditor_codigo`.
- Causa: `sourceGeneration` solo avanzaba al comenzar el closure serializado.
  Si un seek bloqueaba la cola, un cambio solicitado todavía dejaba vigente la
  revisión anterior.
- Corrección: `mediaContextRevision` incrementa al invocar `open` o
  `switchSource`, antes de entrar a `_serialize`. Los valores del menú llevan
  esa revisión.
- Regresión: seek fake bloqueado → petición A→B → selección del item de A antes
  de liberar la cola. La selección se descarta; el engine no recibe el ID y la
  UI no muestra el mensaje. Después se libera el seek y se verifica B activa.
- Revisión independiente posterior: pasó; no encontró P1/P2 residual en esta
  carrera.

### F27-SW-03 — P2, corregido: Stop pendiente dejaba activo el menú

- Encontrado en segunda pasada independiente `auditor_codigo` como riesgo
  separado del cambio A→B.
- Corrección: la solicitud de Stop también incrementa
  `mediaContextRevision` de manera síncrona.
- Regresión: seek fake bloqueado → Stop solicitado → selección antigua. No se
  llama al engine ni aparece el mensaje; al liberar la cola, el snapshot queda
  detenido. El revisor independiente confirma que el test pasa y no encontró
  regresiones P1/P2 en ese ajuste.

### Riesgo nativo restante fuera de esta causa

`media_kit 1.2.6` expone `Player.stream.error` como texto sin identidad de
fuente. La revisión por generación de aplicación no correlaciona con certeza un
evento nativo tardío A/B. Este riesgo previo de F2.7 sigue abierto y no se
declara resuelto por las protecciones UI.

## Recorrido real de cambio de servidor

La integración usa Morevna Episode 3 real, dos servidores HTTP de loopback
independientes que entregan el mismo archivo, más el endpoint de fallo 503.
Solicita posición 00:40 y ejecuta:

1. A→B y B→A con reproducción activa.
2. Pausa, A→B, confirma pausa y posición; Play.
3. Seek -10/+10 tras cambiar de fuente.
4. Ciclos A→B→A repetidos con `positionDelta <= 2s`.
5. Selección del endpoint C con 503 y restauración de la fuente previa.
6. Comprueba `sourceUri`, estado Play/Pause, pistas preservadas y `error == null`.

El recorrido terminó satisfactoriamente con libmpv. Esto verifica motor y
coordinator; no representa clics gráficos ni escucha de salida de audio.
