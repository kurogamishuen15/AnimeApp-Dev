## Misión F0-FINAL — verificación adicional

Fecha: 2026-11-08

La sesión actual verificó raíz Git, `main` en `29cbcf3` y cambios concurrentes aún sin stage en `.codex/agents/`, `AGENTS.md` y `docs/ai-system/`; se preservaron.

### SDK de análisis

Se repitió `flutter --version`: stable 3.47.9, framework `c197ca5199e9ee5661e865596c9c07294dfab51c`, Dart 3.13.7. `flutter analyze` local sigue fallando, `dart analyze lib test` pasa. La metadata oficial lista stable 3.47.9 y beta 3.50.0-0.4.pre (Dart 3.14); el changelog de stable 3.47.9 no menciona #191377. La stable instalada aún reproduce el error. El beta cumple el rango `^3.13.7`, pero la prueba aislada no fue viable durante esta misión: archive oficial 1,516,903,176 bytes, descarga observada ~0.3 MiB/s (más de 1h estimada). Se canceló tras ~7.7 MiB, se retiró el archivo parcial creado para la prueba y no se tocó el SDK global. No se afirma que el beta contenga la fix ni pase los tests sin una ejecución real.

### Ventana Wayland

`DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-0`, `XDG_SESSION_TYPE=wayland`. `xdotool`/`xprop` enumeran solo ventanas Xwayland; `wayland-info` está disponible. Se lanzó `flutter run -d linux` con proceso y Flutter VM Service, luego Spectacle `--background --activewindow` capturó exactamente la ventana activa. La captura inspeccionada mide 1280×768 y muestra barra GTK `anime_app`, título AnimeApp, icono, nombre y texto inicial. Evidencia durable: `docs/perf/wayland-window-20261108.png`. Esto confirma ventana y contenido estático visibles en el compositor. No prueba controles interactivos (no los hay) ni tiempo de presentación; el TSV conserva launch-to-window NA.

`flutter screenshot --type=skia` se intentó contra el VM Service pero falló: `Cannot capture SKP screenshot with Impeller enabled`; el crash log `app/flutter_01.log` generado por esta ejecución se retiró tras registrar el fallo. Se terminó `flutter run`; no quedó proceso AnimeApp. La captura temporal de `.ai-local/` se copió a docs/perf y el temporal se retiró.
