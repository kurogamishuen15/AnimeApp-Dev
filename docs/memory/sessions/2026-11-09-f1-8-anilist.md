## Implementación

- Añadido Dio 5.11.1; el cliente GraphQL propio envía una consulta POST con
  variables y datos mínimos de títulos/ID. No hace autenticación, mutation,
  prefetch, scraping o logging de payload.
- El dominio define `AnimeSummary`, `AnimeSearchResult` y el port
  `AnimeCatalogRepository`, independiente de Dio/GraphQL/Drift.
- Errores de transporte, timeout, 429/Retry-After, outage 403, errores GraphQL
  y envelopes malformados se distinguen; los títulos ausentes son nullable.
- Un gate compartido por proceso empieza con dos segundos entre solicitudes,
  se adapta a `X-RateLimit-Limit`, obedece `Retry-After` y no reintenta solo.
- Cache local `latest_anime_search` reemplaza un único resultado de búsqueda
  explícita. El fallback exige coincidencia de texto, página y tamaño, y expone
  fuente `localCache` y el error de refresco. No conserva historial.
- Drift sube a schema v3. Se conservan snapshots históricos v1 y v2; se prueba
  migración v1→actual y v2→v3, además de crear/cerrar/reabrir.
- No se conecta el adapter al composition root o UI. Tests usan loopback HTTP;
  no se contactó `graphql.anilist.co`.

## Fuentes de política vigentes

- [GraphQL Getting Started](https://docs.anilist.co/guide/graphql/): POST a
  `https://graphql.anilist.co`, con `query` y `variables`.
- [Rate Limiting](https://docs.anilist.co/guide/rate-limiting): la guía informa
  una medida temporal de 30 requests/minuto pese a límite nominal 90/minuto;
  permite leer `X-RateLimit-*` y `Retry-After`.
- [Terms of Use](https://docs.anilist.co/guide/terms-of-use): prohíbe uso como
  backup/data storage y servicios competidores no complementarios de listas o
  tracking. La elegibilidad concreta de AnimeApp no se verificó; no se hizo
  smoke test real ni se conecta el cliente a producto hasta revisión propietaria.
